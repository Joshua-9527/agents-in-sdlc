Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行しながら自律的に作業します。VS Code の Copilot Chat では、ローカルで行われる作業の各ツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を採用または却下し、エディターを離れずに追加のプロンプトで作業を調整できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッション中にエージェントへ指示し、ハイコントラストに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも追加します。新しい会話を始める代わりに、現在のセッションに指示して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが確認するファイル、実行するコマンド、提案する編集が表示されます。各ファイルの編集は差分と **Keep** / **Undo** の操作とともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業する様子を確認します。ファイルの読み取り、編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がインライン表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの使用（ターミナルコマンドの実行など）に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するのは、実行してもよいコマンドだけにしてください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードが実装されたので、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けることで、エージェントは変更したコンポーネント、スタイルの方針、local storage の使い方など、前の作業のコンテキストを保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を調べて、ライトモードの追加を提案します。
3. ハイコントラストモードと同様に、変更をレビューします。差分ごとに **Keep** または **Undo** を使います。
4. エージェントの方向が意図と異なる場合（たとえば切り替え UI を希望と異なる形でリファクタリングする場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、補足プロンプトを送ります。

> [!TIP]
> 作業中のセッションを調整すると、最初からやり直すより短時間で進められます。追加プロンプトで、CSS の簡素化（セレクターの複製ではなく CSS 変数を使用する）、方針の修正（3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを追加する）、範囲の拡張（両方の切り替えにキーボードショートカットを追加する）などを依頼できます。

## 作業内容をレビューする

commit する前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ指針である ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージして commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、作業中のセッションを監視し、各ファイルの編集をレビューし、変更を採用または却下し、コンテキストを失わずに作業を拡張するプロンプトを送りました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 作業中のセッションに追加プロンプトを送り、方向を調整しました。

[次のレッスン][next-lesson]では、アクセシビリティ作業を pull request として公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
